# SLA — Seat-monitoring starter (additive, does not overwrite your teammate's files)

This is **batch 1 only**: manual provisional anchor review, Roboflow Workflow image/video inference, seat ID matching, and local JSON output. It **does not** send updates to FastAPI or MongoDB yet and **does not** implement RSVP. These will follow only after confirming the correct camera output and the newest backend schema.

### Prerequisites

- Python 3.11 virtual environment active
- `python -m pip install Pillow` for map preview
- `python -m pip install inference-sdk opencv-python` for Roboflow inference + video

### From SLA project root (Windows PowerShell)

Put `room.jpeg` at the project root, or change the `--image` path below.

**Review the provisional chair anchors** (requires no Roboflow API key):

```powershell
python camera_cloud_capture\seat_monitor_v1\seat_pipeline.py preview --image room.jpeg
```

Open `camera_cloud_capture\seat_monitor_v1\_outputs\seat_map_preview.jpg`. Inspect/edit seat IDs and `[x,y]` normalized anchors in `camera_cloud_capture\seat_monitor_v1\seat_map.json` (range 0–1). The sample is based on one previously uploaded room photo, not auto-generated by a model.

**Run Roboflow model on a real image**, *after you create a Roboflow Workflow with General Detection and obtain a WORKSPACE and WORKFLOW ID*, in PowerShell (use your own values; do not paste keys in chat):

```powershell
$env:ROBOFLOW_API_KEY = "<your-key>"
$env:ROBOFLOW_WORKSPACE = "<your-workspace>"
$env:ROBOFLOW_WORKFLOW_ID = "<your-workflow-id>"
python camera_cloud_capture\seat_monitor_v1\seat_pipeline.py image --image room.jpeg
```

Outputs: `camera_cloud_capture\seat_monitor_v1\_outputs\raw_roboflow_response.json` and `camera_cloud_capture\seat_monitor_v1\_outputs\latest_occupancy.json`. Keep the raw response, which will help us confirm the exact response schema. Never commit your API key. Note that Roboflow serverless inference sends these frames to Roboflow; use images/videos you're authorized to upload.

**Process a recorded video** from the *same fixed camera viewpoint*:

```powershell
python camera_cloud_capture\seat_monitor_v1\seat_pipeline.py video --video "C:\path\to\hall.mp4" --interval 2
```

Output: `camera_cloud_capture\seat_monitor_v1\_outputs\video_occupancy_frames.json` with one prediction snapshot every ~2 seconds. These calls may consume credits. Detection matching is provisional (nearest chair center) and must be validated: camera motion, occlusions or missed detections cause uncertainty. Unmatched seats are `UNKNOWN`, not `AVAILABLE`.

**Reprocess a saved Workflow response without making another API call**:

```powershell
python camera_cloud_capture\seat_monitor_v1\seat_pipeline.py from-json --image room.jpeg --predictions camera_cloud_capture\seat_monitor_v1\_outputs\raw_roboflow_response.json
```

### Important limitations

- The Roboflow **Seat Analysis** Universe project shows **0 trained models**. Its demo says **Powered by general detection model** and provides a `run_workflow(...)` template with placeholders for workspace/workflow. You need your own configured Workflow ID (or eventually a trained model), not just `seat-analysis/1`.
- `SPOT_HELD` (bags/laptops) cannot be inferred from those chair classes alone.
- The photo map is a provisional **manual mapping**, not a trained chair detector. Have the administrator review the anchors.
- Model class names and JSON output shape must be validated on your real footage before integration with the MongoDB and React system.
- Do not commit `camera_cloud_capture/seat_monitor_v1/_outputs`, personal videos, or API keys to a shared public repository.
